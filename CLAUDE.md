# Pysanka — правила роботи

- Простими словами, українською. У текстах для людей (рядки застосунку, README, нотатки релізу) якнайменше тире «—»: краще двокрапка, кома чи нове речення. «Спершу дай відповідь, нічого не змінюй» — лише відповідай; зміни після «згодна». Перед великими або незворотними кроками питай.
- Жодних особистих подробиць власниці в коді, документах, комітах і релізах. Лише загальні або вигадані приклади. Документація коротка й описує актуальний застосунок.
- Після кожної зміни перевіряти, чи треба оновити README, опис репозиторію на GitHub і нотатки релізу (`.github/release-notes.md`).
- Без дозволу на інтернет (`tools:node="remove"` у маніфесті, збірка зупиняється, якщо він з'явиться), мінімум дозволів. Новий дозвіл — лише разом із функцією, яку людина вмикає сама, і з рядком у `.github/check-permissions.sh` та `SPEC.md`.
- Те, що людина набирає, нікуди не записується без потреби. Поля пароля, режим інкогніто й поля з позначкою «не вчитися» не потрапляють ні в словник, ні в буфер, ні в ШІ.
- Збережене (буфер, вивчені слова, зразки стилю) завжди зашифроване; ключ в Android Keystore. Лише перевірені криптобібліотеки.
- Модель ШІ (Gemma) людина завантажує сама; приймається лише точний файл за SHA-256 закріпленої ревізії. Без неї клавіатура працює повністю. Вбудовані моделі (розпізнавання тексту, Whisper base для диктування) — лише закріплені файли з SHA-256 поруч, перевіряються під час збірки.
- Українська й англійська в інтерфейсі, без русизмів і російських слів. Інші мови й розкладки — з FlorisBoard.
- Шифрування, ключі, дозволи, буфер і важливі зміни перевіряє незалежний аудит окремим агентом; перед релізом для людей — повний неупереджений аудит (функції, безпека, конфіденційність, помилки, стрункий код).
- Коміти від імені Claude (підписані, «Verified») з рядком `Co-Authored-By: Marybezu <347567161+Marybezu@users.noreply.github.com>`.
- До версії 1.0 користувачів немає: жодного коду для переходу зі старих версій (міграцій, прибирання старих файлів, сумісності); тестові версії просто перевстановлюються.
- Реліз підписується лише в середовищі `release` після схвалення власниці; збірка ключа не бачить. Версія — у `version.txt` (основна.додаткова.виправлення): перед кожним релізом підняти її; ту саму версію вдруге не випустити.
- Основа — FlorisBoard (`upstream`), але Pysanka — самостійний форк: оновлення FlorisBoard не переносяться автоматично, лише точкові виправлення. Простір `dev.patrickgold.florisboard` не перейменовуємо; своє пишемо в `ua.pysanka`, зміни у файлах FlorisBoard позначаємо коментарем `Pysanka:`. Непотрібне вирізаємо; «двигун» (набір, свайп, розкладки, словники) змінюємо лише заради відчутної користі й з тестами.
- Як працює застосунок — `SPEC.md`, рішення й причини — `DECISIONS.md`. Перед змінами звіряйся з ними, після змін онови.
